## 문제별 대조

### 1. 이메일 주소가 화면 제목
- 무엇이 잘못됐나: 스튜디오·성과실 제목과 성과 요약 줄에 로그인 이메일 전체가 노출된다. 390에서는 잘린 채 제목이 된다.
- 왜 잘못인가: 개인정보가 화면 최상위 위계를 차지하고, 제품이 "누구의 무슨 공간"인지 말하지 못한다. 승인 정본 v68은 "콘텐츠 운영 / 기본 작업 공간"이다. Buffer도 계정 정보를 코너 메뉴로 내리고 헤더에는 워크스페이스명만 둔다.
- 어떻게 고쳤나: 제목 = 작업 공간명(콘텐츠 운영 / 기본 작업 공간). 이메일은 계정 아바타를 눌렀을 때 팝오버 안에서 가린 형태(so******@gmail.com)로만 보이고, "작업 공간 이름 바꾸기"를 같은 메뉴에 뒀다. 성과 요약 줄도 "성과 요약 · 기본 작업 공간 · 최근 30일"로 교체.

### 2. 쿠키 동의 배너가 담당 패널을 덮음
- 무엇이 잘못됐나: 우하단 배너가 담당 패널의 입력창·보내기 버튼을 가린다. 390에서는 하단 절반을 덮는다.
- 왜 잘못인가: 동의 UI가 제품의 핵심 인터랙션을 차단한다. 코너 배치는 본문 흐름을 막지 않는 것이 통례이고, 동의·거부 버튼은 동일한 시각 무게여야 한다(2025 GDPR 판례 방향).
- 어떻게 고쳤나: 좌하단 코너 카드(340px)로 이동해 우측 담당 패널과 겹치지 않게 했다. 동의·거부를 같은 크기·같은 스타일로. 390은 압축 하단 시트(약 130px, 종전 대비 절반 이하)로 하고 한 번 선택하면 사라진다.

### 3. 시안에 없는 상단 칩 줄 + 내부 용어 노출
- 무엇이 잘못됐나: "승인 인박스 / 발행 캘린더 / 발행실 / AI 공유 Claude CLI" 칩 줄이 4단계 표시 위에 한 줄 더 있다. 이동 수단이 두 겹이고, 내부 도구 용어가 고객 화면에 노출됐다.
- 왜 잘못인가: v67 정본은 "낱개 표면을 4단계 셸로 흡수"가 결정이었다. 칩 줄은 그 결정의 역행이고, 내부 용어는 고객이 이해할 수 없는 정보다.
- 어떻게 고쳤나: 칩 줄 삭제. 승인 인박스 → 톱바 우측 "검토" 버튼(배지 1), 발행 캘린더 → "일정" 버튼으로 이동해 기능은 보존. "AI 공유 Claude CLI"는 고객 화면에서 제거하고 설정(AI 엔진) 화면 소관으로 옮긴다. 이동은 4단계 표시 하나만 남는다.

### 4. 좌측 세로 막대의 0/5, 0/3, 0/2
- 무엇이 잘못됐나: 아이콘 무리 위에 라벨 없는 분수가 떠 있다.
- 왜 잘못인가: 화면 안에서 해독 불가능한 숫자는 정보가 아니라 소음이다(분모가 채널 그룹 수라는 것을 알 길이 없다).
- 어떻게 고쳤나: v68 다크 아이콘 레일(작업/학습/설정/도움)을 상속해 숫자를 제거했다. 채널 연결 수는 본문 시작 스트립에 "채널 연결 0/15"로 라벨과 함께 1곳에서만 보여준다.

### 5. 성과실 지표 4칸 전부 "미수집"
- 무엇이 잘못됐나: 같은 빈 상태 문구가 지표 자리마다 반복된다.
- 왜 잘못인가: 원인(채널 미연결)은 하나인데 증상을 네 번 말한다. 빈 상태는 방치 화면이 아니라 첫 행동 유도 화면이어야 한다. Buffer는 "No Data Found" 안내를 1회만 주고, Hootsuite는 빈 지표 대신 데모 데이터 프리뷰를 보여주는 방향으로 온보딩을 개선했다.
- 어떻게 고쳤나: 안내 카드 1개("아직 성과를 수집할 채널이 없습니다" + 채널 연결하기 CTA + "첫 수집까지 시간이 걸립니다")로 원인을 한 번만 설명하고, 지표 그리드는 "예시 데이터" 배지를 단 회색 프리뷰로 채워 연결 후 모습을 미리 보여준다. 채널 필터는 비활성 처리(회색)로 남긴다.

### 6. 상단이 무겁다 (미연결 배너 + 온보딩 줄)
- 무엇이 잘못됐나: 15개 미연결 배너와 온보딩 진행 줄(1/5)이 겹쳐 본문이 밀린다. 390에서는 상단 적층이 화면 40%를 먹는다.
- 왜 잘못인가: 같은 목적(연결·시작 유도)의 배너 두 개는 중복이고, 본문(작업)이 화면의 주인이어야 한다.
- 어떻게 고쳤나: 하나의 시작 스트립 한 줄로 통합 — "시작 1/5 · 다음 할 일: 브랜드 문서 연결 · 채널 연결 0/15 + 채널 연결하기 + 전체 보기". 전체 보기를 누르면 5단계 목록이 펼쳐진다. 390 상단은 2줄(공간명+유틸 / 4단계) 116px로 고정, 본문이 접힘선 위에서 시작한다.

### 7. 미리보기 카드 채널명 잘림 (Thre...)
- 무엇이 잘못됐나: 카드 머리에서 채널 이름이 말줄임된다.
- 왜 잘못인가: 채널 식별이 카드의 1차 정보인데 그것부터 잘린다. 잘라야 한다면 보조 정보(카운터)가 양보해야 한다.
- 어떻게 고쳤나: 채널명은 nowrap 전체 표기, 글자수 카운터(0/500)는 우측 끝 별도 자리로. 연결 CTA는 "Threads 계정 연결하기"처럼 대상을 명시.

### 8. (모바일 추가 확인) 390 상단 밀도·필터 칩 두 줄
- 어떻게 고쳤나: 위 3·6 통합으로 상단 5줄 → 2줄. 필터 칩은 한 줄 가로 스크롤(스크롤바 숨김)로 바꿔 두 줄 깔림을 없앴다. 유틸·아바타 버튼은 44px 터치 타깃 준수.

## 상태·뷰포트 커버리지

- 상태 이름 주의: 프레임 파일명의 before/after는 "수정 전/후"가 아니라 **채널 연결 전/후**다. 8장 전부 v69 개선안이다. 현재 운영 화면(수정 전)은 docs/qa/osmu-live-walk-20260903/live-*.png 가 그 역할이다.
- 프레임 8장: publish·performance × 연결 전·후 × 1024x900·390x844. 쿠키 배너 표시·숨김 토글. loading·error·disabled·overflow 상태는 v68 정본에 이미 정의돼 있어 중복 제작하지 않았다(상속).
- 연결 후 본론 복원(반려 반영, 2026-09-03): v68 정본의 "잘된 콘텐츠 세 개 + 다음 행동과 반응 관리" 두 카드를 성과실 연결 후 화면에 그대로 상속해 채널별 보기 아래 공백을 없앴다. 발행실 연결 후 카드에는 v67 정본의 계정 행(아바타·계정명·연결됨)과 채운 본문 미리보기를 복원했다. 계정명·핸들은 가린 예시(@example_official)를 쓴다.
- 뷰포트: 1024x900, 390x844 뷰포트 컷(전체 페이지 캡처 아님). clean=1 파라미터로 크롬·토글·변경점 패널·STAMP 제거 내보내기.
