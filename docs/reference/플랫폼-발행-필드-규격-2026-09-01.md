# 플랫폼 발행 필드 규격

기준일은 2026-09-01이다. 이 문서는 OSMU 발행실이 현재 보여 주는 7개 미리보기인 Threads, X, Instagram, Facebook, YouTube Shorts, Instagram Reels, TikTok을 대상으로 한다.

## 판정 원칙

- `하드 제한`은 공식 게시 또는 업로드 문서가 수치로 명시한 값이다. 초과 시 발행을 막는다.
- `권고`는 공식 도움말의 모범 사례다. 초과해도 발행을 막지 않고 경고한다.
- `규격 확인 필요`는 공식 문서에서 현재 지원 범위에 맞는 수치를 확인하지 못한 값이다. 임의 상한과 분모를 표시하지 않는다.
- 해시태그가 캡션이나 본문에 포함되는 플랫폼은 합친 최종 문자열을 본문 한도에 포함한다.
- 표시 이름과 사용자명은 연결 계정의 정보다. 게시물 편집 필드가 아니다. 게시물 작성 화면에서는 읽기 전용으로만 보여 준다.

## 표시 이름과 사용자명 소유권

`API로 바꿀 수 있는가`는 게시물 발행 API 기준으로 판정한다. 계정 설정 API가 별도로 있더라도 발행실에 계정 변경 입력을 만들 근거는 되지 않는다.

| 플랫폼 | 공식 API에서 읽는 계정 정보 | 발행 API로 변경 가능한가 | 발행실 계약 | 공식 출처 |
|---|---|---|---|---|
| Threads | 프로필의 사용자명, 이름, 프로필 사진 | 아니오. 게시물 생성 입력은 본문, 미디어, 주제 태그이며 프로필 수정 입력이 아니다. | OAuth로 연결한 계정의 이름과 사용자명을 읽기 전용으로 표시 | [Threads 프로필](https://developers.facebook.com/docs/threads/threads-profiles), [Threads 게시물](https://developers.facebook.com/docs/threads/posts) |
| X | `GET /2/users/me`의 `name`, `username`, `profile_image_url` | 현재 X API v2 게시물 생성과 사용자 조회 문서에는 프로필 이름 또는 사용자명 수정 입력이 없다. 별도 계정 설정은 발행실 범위가 아니다. | 읽기 전용. 변경 안내는 X 계정 설정으로 보냄 | [인증 사용자 조회](https://docs.x.com/x-api/users/lookup/quickstart/authenticated-lookup), [게시물 생성](https://docs.x.com/x-api/posts/create-post) |
| Instagram | IG User의 `name`, `username`, `profile_picture_url` | 아니오. 미디어 생성과 게시 입력에 프로필 수정 필드가 없다. | 읽기 전용. Instagram 계정에서 관리 | [IG User](https://developers.facebook.com/docs/instagram-api/reference/ig-user), [미디어 생성](https://developers.facebook.com/docs/instagram-api/reference/ig-user/media) |
| Facebook | Page의 `name`, `username`, `picture` | 아니오. Page Feed 게시 입력은 Page 프로필 수정 입력이 아니다. | 읽기 전용. Facebook 페이지 설정에서 관리 | [Page](https://developers.facebook.com/docs/graph-api/reference/page), [Page Feed](https://developers.facebook.com/docs/graph-api/reference/page/feed) |
| YouTube | Channel의 `snippet.title`, `snippet.customUrl`, 썸네일 | 아니오. `channels.update`는 채널 제목을 바꾸면 `channelTitleUpdateForbidden` 오류를 반환한다. 핸들 수정도 Data API 발행 입력이 아니다. | 읽기 전용. YouTube Studio에서 관리 | [Channels](https://developers.google.com/youtube/v3/docs/channels), [Channels update](https://developers.google.com/youtube/v3/docs/channels/update) |
| TikTok | Creator Info의 `creator_nickname`, `creator_username`, 아바타 | 아니오. Display API와 Creator Info는 조회용이며 Direct Post는 콘텐츠와 공개 설정을 보낸다. | 읽기 전용. TikTok 계정에서 관리 | [Content Posting 시작하기](https://developers.tiktok.com/docs/en/content-posting-api-get-started), [Display API](https://developers.tiktok.com/docs/en/display-api-overview) |

Instagram 피드와 Reels는 같은 Instagram 연결 계정을 공유하므로 계정 정보 행은 하나로 합쳤다.

## 화면 반영 계약

1. 미리보기 머리의 표시 이름 입력과 사용자명 입력은 삭제한다.
2. 계정 머리는 `아바타, 표시 이름, @사용자명, 읽기 전용 안내` 순서의 행이다.
3. 계정 정보가 없으면 가짜 이름을 만들지 않는다. `계정 연결하기`, `계정 정보 불러오는 중`, `계정 정보를 불러오지 못했어요` 세 상태 중 하나를 보여 준다.
4. 별도 해시태그 입력을 제공해도 최종 게시 문자열의 텍스트 한도에는 합쳐서 계산한다.
5. 규격을 확인하지 못한 값은 분모 없는 `규격 확인 필요`로 표시한다. 임의 숫자로 입력을 막지 않는다.
6. `승인 인박스`는 사용자 화면에서 `검토 대기`로 바꾸고 행동은 `검토 요청하기`로 쓴다.
7. `운영자 API`는 사용자 화면에서 쓰지 않는다. 연결이 아직 준비되지 않은 상태는 `플랫폼 연결 준비 중`으로 쓴다.

## 레드팀

까다로운 고객의 공격: 숫자가 없는 Facebook 규격은 검증을 포기한 것처럼 보이고, 읽기 전용 계정 이름은 잘못 연결했을 때 답답하다.

수정: 확인하지 못한 숫자는 분명히 `규격 확인 필요`라고 표시하되, 업로드 직전 API 사전 검증 결과를 같은 자리에서 보여 준다. 계정 이름 행에는 편집 대신 `연결 계정 바꾸기` 행동을 둔다. 게시물 필드와 계정 교체를 섞지 않는다.

## 셀프심문

질문: 내가 적은 규격 중 출처 없이 기억으로 쓴 값이 있는가?

답: 없다. Threads, X, Instagram, YouTube Shorts, TikTok의 수치는 각 행의 공식 문서에서 확인했다. Facebook 일반 페이지 본문, Facebook 해시태그 개수, TikTok 해시태그 개수는 공식 고정 상한을 확인하지 못했으므로 숫자를 쓰지 않고 `규격 확인 필요`로 남겼다. YouTube 설명은 도움말의 `5,000 characters` 대신 Data API 리소스가 명시하는 `5,000 bytes`를 구현 기준으로 채택했다.

이 결론이 틀렸다면 가장 그럴듯한 이유: 플랫폼 문서가 계정 등급과 API 버전에 따라 다른 제한을 돌려주는 경우다. 이를 막기 위해 TikTok 영상 길이는 최신 Creator Info 응답을 우선하고, 고정 숫자는 공식 문서가 계정 공통이라고 밝힌 값에만 사용한다.
