| 완성 링크 (게시물·댓글용, 예비) | 규격만 예약. 이번 바퀴 발행 없음 | `…/?utm_source={threads|instagram}&utm_medium=post&utm_campaign=osmu-2026-09-receipt` (가설 C용) · `…&utm_campaign=osmu-2026-09-report` (가설 D용). 두 캠페인 값 정규식 통과 확인 | 미개통(다음 바퀴, 제품 실발행 관찰 후) |
| 유입 태그 | 코드 실측 + 운영 실측 | 운영 `/` 에 위 링크로 접속 시 최종 URL 에 `utm_source`·`utm_medium`·`utm_campaign` 3개 보존(2.1 표). GA4 콘솔에서 `세션 소스/매체 = threads / bio` 로 잡히는지는 §5-1 ⑤ 회장 관측 | 도착지 보존 **개통** · 콘솔 귀속 **미확인** |
| 행동 관찰 | 기존 코드(`lib/analytics/`) | 설치 확인 = 운영 번들에 측정 ID·gtag 로더·동의 코드 존재(2.1). 동작 확인 = 회장이 배너 동의 후 GA4 실시간 보고서에 `page_view` 1건이 뜨는 것(§5-1 ④). 내부 트래픽 필터 = §5-1 ③ | 설치 **개통** · 동작 **미확인** · 내부 필터 **미개통** |
| 결제 경로 (판매 국면) | 해당 없음 | 사전 시점, 고객 0명, 가격 ADR-003 Proposed 상태 | 해당 없음 |

### 2.3 이번 바퀴 판정 지표 정의 (SQL 대신 GA4 콘솔 경로)

- **지표**: GA4 표준 `page_view` 이벤트 수, 조건 `세션 소스 = threads 또는 instagram` AND `세션 매체 = bio` AND `세션 캠페인 = osmu-factory`, 기간 = bio 링크 게시일부터 14일.
- **어디서 보나**: 보고서 → 획득 → 트래픽 획득(세션 소스/매체 차원) 또는 탐색 분석에서 `세션 캠페인` 필터. 첫 관측은 실시간 보고서(가장 빠름, 최근 30분).
- **제외**: `traffic_type = internal`(§5-1 ③ 필터가 Active 이면 자동 제외). 필터 Active 이전의 회장 확인 클릭은 진단서에서 날짜·건수로 수기 제외한다.
- **알고 있는 약점**: ①동의 게이트로 인한 과소 집계. 동의율은 미측정이고 이 벤처에 그 비율을 잴 장치가 없다. 도착 0 판정 시 반증 분기(01 카드)에 "동의 거부" 갈래를 하나 더 둔다: 플랫폼 인사이트 링크 클릭 ≥1, GA4 0 이면 "설치 결함" 이 아니라 "동의 거부" 일 수 있다. 구분하려면 서버 로그(Cloudflare 터널 접근 로그의 `utm_` 쿼리)를 2급 대리로 쓴다. 이번 바퀴는 그 대리 지표를 켜지 않고 약점으로만 기록한다. ②Instagram 인앱 브라우저는 로컬스토리지가 세션마다 초기화되는 경우가 있어 동의 배너가 매번 뜬다. 도착 자체는 배너 앞에서 이미 발생하므로 `page_view` 발행 조건(동의 클릭)만 영향받는다.

## 3. 포맷·CTA 규격 (growth-loop §7.2.4 B, 3칸 소유)

## 5. 회장 수동 절차서 3건

> 콘솔 화면은 추측하지 않는다. 아래는 공식 도움말 경로 기준이고, 화면이 다르면 캡처를 주시면 절차를 고친다. 값(측정 ID·IP)은 이 문서와 채팅에 적지 않는다.

### 5-1. GA4: 속성 소유 확인 + 내부 트래픽 필터 + 실시간 관측 (10분)

① **속성이 회장 계정에 있는지**
- URL: `https://analytics.google.com/`
- 클릭: 왼쪽 아래 톱니 `관리` → 상단 계정/속성 선택기 → 속성 목록.
- 확인할 것: 목록에 이 서비스용 속성이 보이는가. 보이면 ②로. **안 보이면** 시크릿의 측정 ID 가 다른 계정 소유라는 뜻이다. 그 경우 `⛔ 회수` (문서 끝) 옵션 B 로 간다.

② **측정 ID 대조**
- 클릭: `관리` → `데이터 수집 및 수정` → `데이터 스트림` → 웹 스트림 클릭 → 오른쪽 위 `측정 ID` (`G-` 로 시작).
- 대조 대상: GitHub 저장소 `Settings → Secrets and variables → Actions → OSMU_GA4_MEASUREMENT_ID`. 시크릿 값은 화면에 안 보이므로 **직접 대조는 불가**하다. 대신 ④의 실시간 관측이 "같은 속성" 의 증거가 된다(내 방문이 이 속성에 찍히면 번들의 ID 가 이 속성이다).

③ **내부 트래픽 정의 + 필터 Active**
- 클릭: 같은 웹 스트림 화면 → `태그 설정 구성` → `모두 표시` → `내부 트래픽 정의` → `만들기`.
- 입력: 규칙 이름 `chairman-home`, `traffic_type` 값 `internal`(기본), 조건 `IP 주소 다음과 같음` + 지금 쓰는 공인 IP(브라우저에서 `https://whatismyipaddress.com/` 확인). 저장.
- 클릭: `관리` → `데이터 수집 및 수정` → `데이터 필터` → `Internal Traffic` 행 → 상태를 **`테스트` 에서 `활성`으로** 변경 → 저장.
- 확인할 것: 데이터 필터 목록에서 상태가 `활성`. **기본값은 테스트라 그대로 두면 제외되지 않는다**(웹 조사, 문서 끝 출처). 사무실·모바일 데이터 IP 는 잡히지 않으니 확인 클릭은 집 회선에서만.

④ **동작 관측 (설치 ≠ 관측)**
- 브라우저 시크릿 창에서 §2.2 Threads 링크를 그대로 열기 → 하단 "쿠키/분석 사용 동의" 배너에서 `동의` 클릭.
- 클릭: GA4 `보고서` → `실시간`.
- 확인할 것: `최근 30분 사용자` 1 이상, 이벤트 카드에 `page_view`. 이것이 §2.2 "행동 관찰 동작" 을 개통으로 바꾸는 증거다. **주의: ③을 먼저 Active 로 하면 자기 방문이 제외돼 실시간에 안 뜬다.** 순서는 ④ 먼저 → 확인 후 ③.

⑤ **소스/매체 귀속 관측**
- 같은 실시간 화면에서 `사용자 (최초 사용자 소스)` 또는 `세션 소스/매체` 카드에 `threads / bio` 가 뜨는지. 뜨면 유입 태그 콘솔 귀속 **개통**.
- 안 뜨면(수동 `page_view` 가 `page_location` 을 못 실은 경우) 캡처를 주시면 코드 쪽(`ga.ts` config 파라미터) 을 제품 레인에 티켓으로 넘긴다.

⑥ 완료 보고 형식: 캡처 3장(속성 목록 · 데이터 필터 상태 활성 · 실시간 화면). 캡처를 받으면 이 문서 §2.2 상태를 갱신하고 `status: opened` 로 닫는다.

### 5-2. Threads: 프로필 링크 교체 (5분)

- 앱: Threads 앱 → 하단 프로필 탭 → `프로필 수정`. 웹: `https://www.threads.com/` → 왼쪽 프로필 아이콘 → `프로필 수정`.
- 클릭: `링크` 필드.
- 붙여넣을 문자열(한 글자도 바꾸지 말 것):
  ```
  https://openclaw.sj-onpremise-cloudflare-tunnel.cloud/?utm_source=threads&utm_medium=bio&utm_campaign=osmu-factory
  ```
- bio 본문은 §3.4 Threads 확정본. 이미 같은 문장이면 건드리지 않는다.
- `완료`.
- 확인할 것: 프로필 화면에서 링크를 한 번 탭 → 열린 페이지 주소창에 `utm_source=threads` 가 남아 있는가. Threads 가 링크를 줄여 보여줘도 실제 이동 주소에 쿼리가 있으면 정상.
- 알려진 것: Threads 링크 필드는 1개다. 기존 링크가 있으면 교체된다.

### 5-3. Instagram: 프로필 링크 교체 (5분)

- 앱: Instagram → 프로필 → `프로필 편집` → `링크` → `외부 링크 추가` (또는 기존 링크 편집).
- 붙여넣을 문자열:
  ```
  https://openclaw.sj-onpremise-cloudflare-tunnel.cloud/?utm_source=instagram&utm_medium=bio&utm_campaign=osmu-factory
  ```
- 제목 필드(선택): `OSMU 팩토리에 맡기기`.

대응 1: 이 칸의 산출은 URL 이 아니라 **"켜져 있다고 믿었던 것과 실제로 켜진 것의 차이"** 다. 01·02 는 GA4 속성이 없고 랜딩이 없다고 전제해 배포 예외까지 요청했다. 실측 결과 둘 다 있었고, 대신 이벤트 4종 중 2종이 없고 동의 게이트가 도착을 깎는다는 것이 드러났다. 이걸 모르고 4칸으로 갔으면 첫 진단서가 "도착 0 = 컨셉 실패" 로 오판했을 것이다.

대응 2: 맞다. 이번 바퀴의 판정은 도착이지 가입이 아니고(01 자기심문), 랜딩의 설득력은 획득 관문 바퀴의 일이다. 다만 지적을 받아 §4 에 landing-copy waitlist 페이지를 "획득 관문 바퀴에서 제품 레인 발주" 로 명시했고, 그때는 `waitlist_submit` 이벤트를 코드에 넣는 것이 함께 간다.
