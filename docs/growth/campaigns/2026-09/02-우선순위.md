## 1. 점수표

척도 1~5. 효과 = 인지도 관문(태그 붙은 도착)을 이번 스프린트에 얼마나 움직이나, 또는 다음 판독을 얼마나 가능하게 하나. 확신 = **그 효과가 날 근거의 양**(감이 아니라 문서·실측). 난이도 = 쉬울수록 높음, 기준선 "2 근무일 + 선행 조건 없음 = 5".

| 가설 | 효과 | 확신 | 난이도(쉬울수록 높음) | 합 | 판정 |
|---|---|---|---|---|---|
| A 계측 개통 | 3 | 5 | 3 | **11** | **지목** |
| B 자동 출고 서명 on/off | 4 | 1 | 2 | 7 | 탈락 |
| C 출고 증거 캡처 글 | 3 | 1 | 3 | 7 | 탈락 |
| D 주간 출고 리포트 | 2 | 1 | 3 | 6 | 탈락 |

**점수를 매긴 이유 (한 줄씩)**

- A 효과 3점 이유: 목표가 "태그 붙은 도착 ≥1" 이라 관문 자체를 크게 움직이지 않는다. 대신 B~D 전부의 판독을 가능하게 하는 유일한 카드다(1칸 가설 요약표: B·C·D 선행 조건에 "A 완료"). 관문 이동만 보면 2, 판독 가능화를 더해 3.
- A 확신 5점 이유: 근거가 전부 문서와 실측이다. GA4 무료·UTM 규격 tag-spec.md 실존·landing-copy.md 카피 실존·bio 편집 절차 ADR-005 확정. 선행 조건이 제품 레인에 걸리지 않는다. 2026-07-06 제로원 무링크 9.8만 사고가 "재는 장치 먼저"의 실측 근거.
- A 난이도 3점 이유: 구현 0.5일은 2 근무일 안이다. 그러나 ①회장 수동 3건(GA4 property 생성·bio 교체 2채널)이 회장 시간에 걸리고 ②도착 페이지 1장이 규약상 제품 배포 게이트를 타야 하는데(growth-lane §3.5 "랜딩 코드는 반드시 브랜치, 배포 게이트 그대로") 그 게이트가 qa 미승인 상태라 배포 명령이 ask 로 잡힌다. 회장 예외 승인 1회 없이는 못 켠다. 그래서 5 가 아니라 3.
- B 효과 4점 이유: 네 카드 중 회장 컨셉("이 게시물은 전부 제품이 만들었다")을 가장 직접 검증한다. 판정 기준이 태그 도착 주 3건 + 인게이지먼트 10% 이내 하락으로 growth-log 실험 5 정본을 계승한다. on/off 교차라 방향 판독이 가능하다.
- B 확신 1점 이유: 선행 조건 "제품 실발행 관찰 ≥1" 이 이번 스프린트 안에 충족될 근거가 0 이다. 제품 레인은 qa 단계에서 코드 리뷰 BLOCK(MAJOR 17, 그중 큐 파일 파손·`result_unknown` 정체·Threads 이미지 발행 차단은 발행 경로 자체의 결함), 운영 배포 미검증, 다음 소유자가 build 워커. 게다가 판정에 on 2주 + off 2주 = 4주가 필요해 선행 조건이 오늘 충족돼도 스프린트 안에 못 닫는다.
- B 난이도 2점 이유: 서명 플래그 구현 0.5일 자체는 쉽다. 그러나 발행 파이프라인 코드를 만지므로 제품 브랜치·배포 게이트 경유가 필수이고, 그 파이프라인이 지금 BLOCK 대상이다. 건드리면 MAJOR 수정과 충돌한다.
- C 효과 3점 이유: 공유 2배·태그 도착 4건 기준. 표본 4건이라 2배 판정은 노이즈에 튄다(1건 차이로 뒤집힘). 댓글 층 배치는 BRAIN 스레드 설계와 맞지만 효과 크기 근거는 viral-mechanics V5 의 기대치뿐.
- C 확신 1점 이유: 선행 조건 "자동 출고 주 3건 이상" 인데 현재 자동 출고 0건. B 와 같은 제품 레인 의존. 없는 큐를 연출해 캡처하는 것은 1칸 §3 에서 금지했으므로 우회 경로도 없다.
- C 난이도 3점 이유: 주 1회 캡처·업로드 15분은 쉽다. 코드 변경 없음. 다만 캡처 대상이 존재해야 하고 캡처 안에 핸들이 보여야 하는데 계정 리네임 미실행(naming.md) 이라 캡처가 구 핸들로 남는다.
- D 효과 2점 이유: 주 판정이 "24h 신규 팔로워 1.5배" 인데 팔로워는 회장 규율상 성과가 아닌 도달 계열 대리 지표다. 태그 도착 4건은 부수 기준. 필러 5(지표 공개)는 브랜드 정본이라 성장 가설로서의 효과는 1칸 자체가 "부분" 으로 표기했다.
- D 확신 1점 이유: 출고 실적이 없으면 리포트 자체를 못 쓴다(빈 리포트 발행 금지). 현재 출고 실적 0. 표본 4건으로 1.5배 판정은 판단 불가 구간.
- D 난이도 3점 이유: 수기 집계 주 20분, 코드 변경 없음. 그러나 2바퀴 안 자동 집계 전환 규칙(gtm-plan 단계 4)이 붙어 있어 뒤로 갈수록 제품 의존이 생긴다.

### 1.1 1칸 추천 재검증 결과

1칸 추천 = A. 이 칸 점수 결과 = A. **같지만 이유가 하나 추가되고 하나 약해졌다.**

- 추가된 이유: 제품 레인 일정을 확신 축에 넣으니 B·C·D 확신이 전부 1 로 떨어졌다. 1칸은 "판독 불가"라는 논리 의존만 봤고, "언제 풀리나"를 안 봤다. 제품이 qa BLOCK 인 한 B~D 는 이번 바퀴뿐 아니라 다음 바퀴도 못 열 수 있다.
- 약해진 이유: 1칸은 A 를 "돈 0, 회장 수동 3건이면 끝" 으로 봤다. 이 칸에서 도착 페이지 배포가 제품 배포 게이트를 타야 한다는 규약(growth-lane §3.5)과 그 게이트가 잠긴 상태를 대조하니 A 도 회장 예외 승인 1회가 필요하다. 난이도 3.
- **A 가 쉬워서 고른 것이 아니다** (ICE 함정 "저열매만 따기" 자기점검): 합계 차이 11 대 7 은 난이도(3 대 2~3)가 아니라 확신(5 대 1)에서 난다. 확신 축을 빼고 효과+난이도만 봐도 A 6, B 6, C 6, D 5 로 동률이며, 동률을 가르는 것은 "지금 근거가 있는가" 뿐이다.

## 2. 이번 바퀴 지목

**가설 A · 계측 개통: 태그 붙은 도착이 0에서 1로 관측된다**

- 겨냥 관문: 인지도 (Awareness). 측정 단위 = GA4 `page_view` with `utm_source ∈ {threads, instagram}` and `utm_campaign=osmu-factory`. 조회·도달·팔로워는 판정에 쓰지 않는다.
- 집행 시점: **사전**. 출력은 획득 관문이 아니라 디스커버리·기획 입력으로 되돌아간다(§7.4). 이 바퀴가 제품 레인에 되돌리는 입력 1줄 = "메타 데모 컨셉의 전제(제품이 발행한다)가 아직 관찰되지 않았다. 제품이 먼저 낼 것 = 외부 채널 실발행 관찰 1건". 제품 `pipeline-state.osmu.md` 는 이 레인이 건드리지 않고, 컨트롤러가 전달한다.
- 트랙: **릴리즈 연동** (2026-09 스프린트 폴더). 상시 트랙은 이 벤처에 아직 없다.
- 완료 기준(3칸으로 넘기는 것): ①GA4 property 존재 ②도착 페이지 1장 라이브(임시 호스트 허용) ③bio 링크 2채널의 태그 실문자열 확인 ④GA4 실시간 보고서에서 `utm_source` 파라미터가 찍히는 것을 **직접 관찰**(설치 완료 ≠ 관측 완료, 실수.md 2026-09-11) ⑤내부 트래픽 필터 적용 기록.
- 판정 시한: 개통 후 14일. 반증 분기는 1칸 카드 그대로(링크 클릭 ≥1 인데 GA4 0 → 설치 결함 / 클릭 0 → bio 경로 가정 기각, `utm_medium=post` 로 전환).
- 알고 있는 약점: 표본 목표가 1건이라 "성공" 판정이 성과를 뜻하지 않는다. 이 바퀴의 성공은 "재는 장치가 켜졌다" 이고 그 이상을 주장하지 않는다.

## 4. 회장 확인

- [ ] 회장이 이 지목을 확인했다 (날짜: )

**회장은 이 칸에서만 본다.** 이후 검수 칸까지 관여하지 않는다. 회장 확인 상한(스프린트당 2회) 중 1회를 여기서 쓰므로 회장이 답할 것을 아래 3건으로 묶었다. 3건 다 "예" 면 3칸으로 간다.

### 회장 확인 요청 (3건, 평문)

**1. 이번 바퀴 지목 = 가설 A(계측 개통) 확인**
- 무엇을: 2026-09 스프린트에서 OSMU 그로스 레인이 하는 일을 "GA4 + 도착 페이지 1장 + 태그 붙은 bio 링크" 개통 하나로 한정하는 것.
- 하면: 3칸 개통 착수. 14일 안에 태그 붙은 도착 1건이 찍히는지로 판독. B~D 는 제품 실발행이 관찰되면 다음 바퀴에 올린다.
- 안 하면: 대안은 B(자동 출고 서명)인데 제품이 실발행을 못 하는 지금은 착수 자체가 불가능하고, 수동 글에 서명을 붙이면 컨셉이 첫날 거짓이 된다. 사실상 이번 바퀴를 비우는 것과 같다.
- 추천: **확인**. 근거는 §1 점수표(A 11 대 B 7)와 제품 레인 qa BLOCK 상태.

**2. 회장 수동 작업 3건 동의 (ADR-005: 계정·bio 편집은 회장만)**
- 무엇을: ①GA4 property 1개를 회장 Google 계정에서 생성 ②Threads·Instagram bio 링크를 3칸에서 발급한 태그 링크로 교체(2채널) ③osmu.kr 도메인 등록 여부.
- 하면: ①②는 3칸에서 링크 실문자열과 클릭 경로를 준비해 드리면 각 5분. ③은 등록하면 정식 주소로 개통, 안 하면 임시 호스트(기존 배포 인프라 하위 경로)로 먼저 개통하고 등록 뒤 리다이렉트.
- 안 하면: ①없으면 도착을 아무것도 못 잰다(A 전체 무효). ②없으면 링크가 아무 데도 안 걸려 있어 도착 0 이 "계측 결함"인지 "경로 없음"인지 구분 불가. ③은 안 해도 이 바퀴 진행 가능.
- 추천: ①② **동의**, ③은 **이번 바퀴 미등록, 임시 호스트로 개통**. 도메인은 돈이 들고 되돌리기 비싼 이름 결정이라 랜딩이 실제로 도착을 받는 것을 본 뒤 정해도 늦지 않다.

**3. qa 미승인 상태에서 정적 도착 페이지 1장 배포 예외 승인**
- 무엇을: 제품 파이프라인은 qa 단계 미승인이라 배포 명령이 ask 로 잡힌다. 그로스 레인 규약은 랜딩 코드도 그 게이트를 타게 한다. 제품 기능은 하나도 안 건드리고 정적 HTML 1장(waitlist 최소형, landing-copy.md 정본 카피)만 별도 브랜치로 배포하는 것을 1회 허용할지.
- 하면: A 를 이번 스프린트 안에 켤 수 있다. 제품 코드·큐·발행 경로와 무관한 정적 파일이라 MAJOR 17건과 충돌하지 않는다. 배포 범위는 그 파일 1장으로 한정하고 집행 로그에 커밋 SHA 를 남긴다.
- 안 하면: A 는 제품 qa 승인 뒤로 밀린다. qa 승인 일정이 미정이므로 이번 스프린트는 계측도 못 켜고 끝난다. 그러면 §7.8 "2스프린트 연속 02 도달 실패 시 레인 폐쇄" 카운트가 시작된다.
- 추천: **승인**. 단 조건 셋: 정적 파일 1장만 / 제품 기능 경로 미변경 / 3칸 개통 확인서에 배포 SHA 와 URL 박제. 만약 도착 페이지를 제품 인프라 밖(별도 정적 호스트)에 두면 이 예외 자체가 불필요하므로, 3칸에서 그 경로가 실물로 가능한지 먼저 확인하고 가능하면 이 항목은 자동 철회한다.

## 레드팀 1회 (회의적 투자자 관점)

> "점수표 네 줄 중 셋이 확신 1 이면 채점이 아니라 형식이다. 처음부터 A 하나뿐이었는데 왜 회장 시간을 이 문서 읽는 데 쓰게 하나. 그리고 배포 게이트 예외를 그로스 레인이 요청하는 것은 게이트 우회 뒷문 아닌가."

대응 1: 셋이 확신 1 인 것이 이 문서의 정보다. 1칸은 B~D 를 "A 뒤에 할 것" 으로 남겼는데, 이 칸은 "제품이 qa 를 못 넘으면 다음 바퀴에도 못 한다" 는 것을 점수로 드러냈다. 그래서 §2 에 제품 레인으로 되돌리는 입력 1줄이 생겼다. 회장이 읽을 것은 §4 3건뿐이고 나머지는 근거다.

대응 2: 뒷문이 아니라 정문에서 승인을 받는 것이다. 규약(growth-lane §3.5)은 랜딩 코드가 배포 게이트를 "그대로 타라" 고 했고, 그 게이트의 이빨은 "qa 미승인 시 배포 명령 ask" 다. ask 에 회장이 답하는 것이 게이트의 설계다. 예외 범위를 정적 파일 1장으로 한정하고 SHA 를 박제하는 조건을 스스로 붙였다. 별도 정적 호스트가 가능하면 이 요청은 철회된다.
