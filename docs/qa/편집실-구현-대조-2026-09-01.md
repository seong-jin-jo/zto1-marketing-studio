## 기존 기능 보존과 변경

- 유지한 기존 기능: 4개 방 셸, 작업물 전체, 학습 정보, 승인 인박스, 발행 캘린더, 형식별 목차, 영상 자막 안전 영역, 장면 빼기와 되살리기, 무음 줄이기, 형식값 저장, 카드의 과거 위치값 읽기.
- 추가하거나 변경한 것: v65 세 열 작업대, 한국어 단위 라벨, 글 연속 문서 편집, 카드 세로 위치 이동, 전체 적용 세 동작, 자동 저장 상태, 단일 발행실 이동, 빈 상태·불러오는 중·오류·긴 내용 계약.
- Backend와 mobile: 수정 없음.

## 셀프심문과 레드팀

질문: 내가 구현한 화면이 v65 설계와 다른 지점이 있는가?

답: v65의 176픽셀 목차, 가변 작업대, 248픽셀 담당 열, 390픽셀 세로 전환, 네 형식, 글 전체 편집, 카드 캔버스 직접 편집, 세 위치, 자동 저장, 단일 주 행동은 일치한다. 기존 제품의 카드·영상 보조 규격 선택과 장면 빼기 기능은 v65가 지우라고 하지 않았고 회귀 금지 대상이라 보조 제어로 보존했다. 기본 카드 규격과 저장 형식은 v65와 같은 4:5다.

까다로운 고객의 공격: 화면이 맞아 보여도 편집값이 발행실 본문에 이어지지 않으면 죽은 편집기다. 수정: 글, 카드뉴스, 영상 편집값을 원본 발행 상태와 함께 갱신하고, `발행실로 이동`이 초안 저장 API 성공 뒤에만 방을 바꾸도록 연결했다. 페이지 통합 테스트와 실제 브라우저 요청 관찰로 확인했다.

이 결론이 틀렸다면 가장 그럴듯한 이유: 실화면 스모크는 로컬 production build와 차단된 API 응답으로 UI와 요청 본문을 확인한 것이며, 운영 데이터베이스와 실제 고객 세션을 붙인 검증은 아니다. 따라서 build는 끝났지만 운영 완료라고 판단하지 않는다.

벤치마크 적용: Canva의 캔버스 안 텍스트 편집과 정렬 조작을 카드 직접 편집과 세 위치 대체 버튼에 적용했다. Google Docs의 연속 문서 편집 관습을 글 전체 textarea에 적용했다. 플랫폼별 발행 결정은 v65 소유 경계대로 발행실에 남겼다.
