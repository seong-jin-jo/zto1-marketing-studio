## 원인 분석과 교정 원칙

근본 원인은 관독자에게 쉽게 보고하라는 규칙을 표준 기술 용어를 한국어 비유로 재명명하라는 규칙으로 오해한 것이다. 그 결과 검색할 수 없고 원래 개념과 1:1로 대응하지 않는 신조어가 생겼다.

교정 원칙은 다음 세 가지다.

1. 표준 기술 용어를 그대로 쓴다. 설명이 필요하면 첫 등장에서만 괄호로 보충한다.
2. 구성 요소, 상태 판정, 재시작 주체를 합쳐 부르지 않는다. `healthcheck`, Docker health status, autoheal restart를 분리한다.
3. 확인한 구성과 운영 상태를 분리한다. 저장소에 있는 workflow 정의는 근거 확인, 실제 운영 환경의 변수 주입과 미디어 왕복은 미검증으로 표시한다.

## 레드팀과 셀프심문

**레드팀 공격.** 단어만 교체하고 구조를 다시 그리면, 이전 보고서의 잘못된 R2 인과관계와 autoheal 책임 범위가 그대로 남는다. 따라서 새 보고서는 단어 대응표만 제시하지 않고 Compose, Dockerfile, GitHub Actions workflow, 미디어 저장 모듈의 실제 계약을 재구성한다.

**셀프심문.** 내가 쓴 설명 중 회장이 이미 아는 것을 굳이 풀어 쓴 문장이 있는가? 있었다. Docker, GitHub Actions, Next.js의 일반 정의를 설명하던 문장을 제거하고, 이 저장소의 값과 경계만 남겼다.
