### 요소와 인터랙션

- 디스플레이: 형식, 반영한 학습 정보 수, A/B/C 구조 초안, 반영한 학습 정보 태그를 읽기 전용으로 보여 준다.
- 생성 담당: 형식, 목적, 대상, 주제, 권리 확인을 한 번에 하나씩 묻는다.
- 구조 초안 선택: A/B/C 선택은 생성 담당에만 둔다. 디스플레이 카드에는 선택 버튼을 두지 않는다.
- 주 행동: 생성 완료 뒤 `편집실에서 다듬기` 하나만 활성화한다.
- 모바일: 첫 두 구조 초안을 우선 노출하고 나머지는 본문 세로 스크롤로 확인한다. 담당은 화면 하단에 유지한다.

### 요소와 인터랙션

- 기본 범위는 채널 전체다. 사용자가 채널 필터를 누르면 같은 지표 구조를 유지한 채 해당 채널로 좁힌다.
- 핵심 지표 네 개를 먼저 보여 주고, 발행·참여·도달·확산은 보조 위계로 둔다.
- 잘된 콘텐츠 세 개는 이유와 학습 정보 제안 가능 여부를 함께 보여 준다.
- 답글 후보와 낮은 반응 콘텐츠는 자동 삭제하지 않는다. 사용자가 직접 검토하고 확정한다.
- 성과 담당은 잘된 이유, 반응 관리 후보, 다음 콘텐츠 제안 중 하나를 설명한다.

## 5. 성과실 정보구조 선택지

| 선택 | 장점 | 비용과 위험 |
|---|---|---|
| A. 네 번째 전용 방으로 세운다. 추천 | 승인된 네 방 모델과 상단 4단계가 일치한다. 성과 설명, 답글 관리, 자동화, 학습 정보 제안을 독립된 작업 공간에 수용한다. Buffer처럼 전체 성과에서 채널별 상세로 좁히기 쉽다. | `/performance`를 실제 화면으로 만들고 홈의 성과 요소를 이동하거나 요약해야 한다. 라우팅과 홈 역할을 함께 정해야 한다. |
| B. 홈 통합을 정본으로 삼는다 | 현재 구현을 가장 적게 바꾼다. 홈 진입 즉시 성과와 준비 상태를 한 번에 볼 수 있다. | 상단 네 번째 방이 홈으로 튀는 구조를 설명하기 어렵다. 온보딩, 채널 준비, 성과 작업이 한 화면에서 경쟁하고 화면 비교의 정본이 흐려진다. |

⛔ 회수 필요: A를 추천하지만 정보구조와 라우팅은 되돌리기 비싼 결정이다. 회장이 A 또는 B를 확정하기 전에는 이 성과실 시안을 승인 정본으로 올리거나 제품 경로를 바꾸지 않는다.

## 6. 근거와 차용

- Canva Magic Design: 콘텐츠 유형과 형식을 먼저 정하고 여러 결과를 비교하는 순서를 생성실에 차용했다. OSMU에서는 템플릿 선택을 그대로 베끼지 않고, 승인된 학습 정보를 반영한 A/B/C 구조 초안으로 바꿨다.
- Buffer Insights: 전체 채널의 고수준 성과에서 단일 채널로 좁히고, 잘된 콘텐츠에서 다음 콘텐츠를 만드는 흐름을 성과실에 차용했다. OSMU에서는 생성실 학습 정보 승인과 답글 관리까지 하나의 피드백 고리로 연결했다.
- UX 심리 근거: Hick의 법칙에 따라 생성 담당은 한 번에 질문 하나만 보여 준다. Zeigarnik 효과는 4단계 상단 상태로 남은 흐름을 보이되, 빈 상태에서 막힌 단계 대신 다음 행동 하나를 제공하는 데만 사용한다.

## 7. 레드팀과 셀프심문

까다로운 고객 공격: “생성 후보 세 개가 기존 화면보다 예뻐 보여도 선택이 카드 안에 들어가면 오른쪽 담당과 역할이 겹친다.” 수정: 카드 안에는 선택 컨트롤을 두지 않고 A/B/C 식별자만 남겼다. 선택은 생성 담당에만 둔다.

회의적 투자자 공격: “성과 화면을 새 방으로 분리하면 구현량만 늘고 홈과 중복될 수 있다.” 수정: 성과실은 후보로만 만들고 A/B의 장단점과 이동 비용을 명시했다. 승인 전까지 홈 또는 `/performance`의 정본을 선언하지 않는다.

셀프심문: 이 설계가 틀렸다면 가장 그럴듯한 이유는 성과실 전용 방이라는 전제가 아직 합의되지 않았기 때문이다. 그래서 clean frame은 비교 가능한 후보 증거로만 쓰고, 정보구조 선택은 회수 항목으로 남겼다.
