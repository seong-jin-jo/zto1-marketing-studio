작성 2026-09-07 23시 · 작성자 Stage Controller (Claude Opus 5) · 근거 = 저장소 코드 전수 확인

## 한 줄

"모든 플랫폼 발행"이 안 되는 이유는 연결이 안 돼서가 아니다. **YouTube·TikTok·LinkedIn은 발행하는 코드가 저장소에 아예 없다.** 연결을 다 붙여도 이 셋은 올라가지 않는다.

## 무엇을 확인했나

`dashboard/src/app/api/publish/route.ts` 의 분기와 `dashboard/src/lib/publish.ts` 의 함수 목록을 대조했다.

| 채널 | 발행 함수 | 발행 경로 연결 | 화면 표시 | 판정 |
|---|---|---|---|---|
| Threads | 있음 | 연결됨 | 발행 가능 | 실제 발행 확인됨 |
| X | 있음 | 연결됨 | 발행 가능 | 요금만 막힘 |
| Instagram (사진) | 있음 | 연결됨 | 발행 가능 | 계정 재연결 필요 |
| Facebook | 있음 | 연결됨 | 발행 가능 | 계정 연결 필요 |
| Bluesky·Telegram·Discord·Slack | 있음 | 연결됨 | 발행 가능 | 계정 미연결 |
| Instagram 릴스 | **있음** | **연결 안 됨** | 미지원 | 코드는 있는데 배선이 없다 |
| YouTube (쇼츠) | 없음 | 없음 | 미지원 | 지어야 한다 |
| TikTok | 없음 | 없음 | 미지원 | 지어야 한다 |
| LinkedIn | 없음 | 없음 | 화면에도 없음 | 지어야 한다 |

`SCHEDULABLE_PLATFORMS` 는 여덟 개다: threads, x, facebook, instagram, bluesky, telegram, discord, slack. 예약 발행도 이 여덟만 다룬다.

## 릴스는 왜 아직 안 붙었나

`publishInstagramReels` 는 이미 구현돼 있고 Meta 공식 폴링 규약(1분 간격 5회)까지 지켜 쓴다. 붙이지 못한 이유는 하나다. **릴스는 공개 HTTPS 영상 주소를 요구하는데, 우리 영상은 서명 배달 주소(`/api/media/<토큰>`)로 나가고 그 주소를 발행 시점에 갱신하는 장치가 이미지에만 있다**(`refreshImageDeliveryUrl`). 영상용 갱신기가 없어서, 붙이면 Meta 가 영상을 받으러 오는 시점에 토큰이 만료돼 실패한다.

즉 릴스를 여는 일은 "분기 한 줄 추가"가 아니라 "영상 배달 주소 갱신기 + 발행 요청에 영상 주소 전달 + 화면 노출" 세 칸이다.

## 회장이 판단할 것

지금 상태에서 "모든 플랫폼"을 채우려면 발행 기능을 셋 새로 지어야 한다. 그것은 연결 작업과 다른 크기의 일이다. 순서를 정해야 한다.

추천 순서와 근거:

1. **인스타그램 사진 발행 복구** — 페르소나 문서에 실명으로 나오는 유일한 채널. 코드는 이미 있고 계정 재연결만 남았다.
2. **인스타그램 릴스** — 영상 생성이 이미 되고 발행 코드도 있다. 세 칸만 채우면 열린다. 같은 채널 안에서 매체가 하나 늘어난다.
3. **YouTube 쇼츠** — 세로 영상을 두 곳에 같이 올리는 그림이 완성된다. 다만 발행 기능을 처음부터 짓는 일이다.
4. **TikTok·LinkedIn** — 계정도 앱도 아직 없다. 앞의 셋이 선 뒤에 본다.

## 미검증

- 릴스·쇼츠·틱톡·링크드인 발행은 실제로 시도해 본 적이 없다. 위 판정은 코드 확인이다.
- 인스타그램 장기 토큰 교환 실패의 원인(전용 앱 시크릿 불일치 가설)은 Meta 콘솔이 비밀번호 재인증을 요구해 확인하지 못했다.
